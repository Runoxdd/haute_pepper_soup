# Fix Next.js Client Component Hydration Errors

## Problem
Next.js build is failing with client component hydration mismatches. The errors indicate that server components are attempting to render client components directly, which is not allowed in Next.js 13+ app directory.

## Root Cause Analysis
- `src/app/admin/menu/page.tsx` is a server component (no "use client" directive) but renders client components `SetupWizard` and `MenuEditor`
- `src/app/admin/catering/page.tsx` is a server component but renders client component `CateringEditor`
- Client components like `SetupWizard`, `MenuEditor`, and `CateringEditor` use React hooks and interactive features that require client-side rendering

## Solution
Convert the affected page components to client components by adding "use client" directives at the top of the files.

## Steps to Fix

### Step 1: Update Menu Admin Page
- Add "use client" directive to `src/app/admin/menu/page.tsx`
- This allows the page to render client components `SetupWizard` and `MenuEditor`

### Step 2: Update Catering Admin Page  
- Add "use client" directive to `src/app/admin/catering/page.tsx`
- This allows the page to render client component `CateringEditor`

### Step 3: Verify Build Success
- Run `pnpm run build` to confirm the hydration errors are resolved
- Test that the admin pages still function correctly in the browser

## Expected Outcome
- Build completes successfully without client component errors
- Admin pages maintain their interactive functionality
- No breaking changes to existing features

## Risk Assessment
- Low risk: Adding "use client" to pages that need interactivity is the standard approach
- These are admin-only pages, so impact is limited to administrative users
- No data fetching or SEO concerns since these are protected admin routes</content>
